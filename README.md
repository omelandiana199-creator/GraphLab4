ЛАБОРАТОРНА РОБОТА №4 

Тема:  Створення графів та алгоритми їх обходу.

Мета:  Навчитися представляти графи у пам'яті комп'ютера, реалізовувати алгоритми обходу графів у глибину (DFS) та в ширину (BFS), визначати властивості графів та розв'язувати прикладні задачі на їх основі. 

Теоретична частина 
Граф - це математична модель, що описує взаємозв’язки між об’єктами. Він складається з: 
  * Вершин (V) - точок або вузлів системи. 
  * Ребер (E) - зв’язків між цими вузлами. 

Для реалізації даної лабораторної роботи було обрано список суміжності як найбільш ефективний спосіб представлення графа. Цей вибір зумовлений такими факторами: 
  * Економія пам'яті: Оскільки досліджуваний граф є розрідженим (кількість наявних зв'язків значно менша за максимально можливу), список суміжності зберігає інформацію лише про існуючі ребра.Це потребує обсягу пам'яті O(V + E), тоді як матриця суміжності завжди займала б O(V^2) місця, зберігаючи велику кількість нулів (відсутніх зв'язків). 
  * Швидкість обробки: Список суміжності дозволяє швидше знаходити сусідні вершини для кожного вузла, що є критично важливим для алгоритмів обходу графа (наприклад, BFS чи DFS). 
  * Гнучкість: Така структура дозволяє легко додавати нові вершини та ребра без необхідності перестворювати всю структуру даних. 

Таким чином, використання списку суміжності забезпечує оптимальний баланс між продуктивністю алгоритмів та витратами ресурсів комп'ютера. 

Практична частина

  * Вершини, що утворюють цикл:  0, 1, 2, 3.

ЗАВДАННЯ 2. Прикладна задача - карта міста 
Список суміжності:  Дороги: 0–1, 0–3, 1–2, 1–4, 2–5, 3–4, 4–6, 5–7, 6–7. 
  0: [1, 3]
  1: [0, 2, 4] 
  2: [1, 5] 
  3: [0, 4] 
  4: [1, 3, 6] 
  5: [2, 7]
  6: [4, 7] 
  7: [5, 6] 

Результати BFS: 
  а) Найкоротший шлях: 0 → 1 → 2 → 5 → 7 (або 0 → 3 → 4 → 6 → 7).
  б) Мінімальна кількість доріг: 4.
BFS-рівні (відстань від вершини 0):
+---------+-----------------------------------+
| Вершина | Відстань від вершини 0 (у ребрах) |
+---------+-----------------------------------+
|    0    |                 0                 |
|    1    |                 1                 | 
|    2    |                 2                 |
|    3    |                 1                 |
|    4    |                 2                 | 
|    5    |                 3                 |
|    6    |                 3                 |
|    7    |                 4                 | 
+---------+-----------------------------------+

DFS-обхід:  Чи відвідає він вершину 7? Так, оскільки граф зв'язний.
Один можливий шлях (в залежності від порядку сусідів): 0 → 1 → 2 → 5 → 7. 

ЗАВДАННЯ 3. Підвищеної складності (6б. Двочастковий граф) 
Умова:  Реалізувати алгоритм визначення, чи є граф двочастковим за допомогою BFS-розфарбовування. 
Граф є двочастковим, якщо його вершини можна розфарбувати у два кольори так, щоб жодні дві суміжні вершини не мали однакового кольору.

Порівняльний аналіз DFS та BFS 

Переваги DFS (пошук у глибину):
  * Використовує менше пам'яті на широких деревах/графах. 
  * Переважно використовується для топологічного сортування, пошуку циклів, генерації лабіринтів та перевірки зв'язності.

Переваги BFS (пошук у ширину): 
  * Гарантовано знаходить найкоротший шлях у незваженому графі. 
  * Ідеально підходить для задач маршрутизації (як у завданні з картою міста) та знаходження об'єктів на заданій відстані.

Обмеження:
  * DFS не гарантує знаходження найкоротшого шляху і може потрапити в нескінченний цикл без масиву відвіданих вершин. 
  * BFS споживає багато пам'яті O(V), якщо граф має високий ступінь розгалуження, оскільки черга зберігає цілі рівні графу. 

Висновки
  * Під час виконання даної лабораторної роботи навчилися програмно представляти графи за допомогою списків суміжності. 
  * Було успішно реалізовано алгоритми обходу графу в глибину (DFS) для виявлення циклів та в ширину (BFS) для знаходження найкоротшого шляху на прикладі карти районів.
  * Додатково було застосовано алгоритм розфарбовування для перевірки графу на двочастковість.
  * Обидва алгоритми мають свої чіткі сфери застосування, і вибір між ними залежить від специфіки конкретної архітектурної задачі.
